01 — Obiettivo

Overview

Fiscal Agent è un assistente conversazionale AI che risponde in tempo reale alle domande fiscali dei clienti Fiscozen, personalizzando ogni risposta con i dati specifici del cliente e il contenuto della knowledge base aziendale.

I consulenti e i clienti Fiscozen si trovano spesso a porre domande ricorrenti su regime forfettario, contributi previdenziali, fatturazione e scadenze. Rispondere manualmente a ogni richiesta richiede tempo e comporta il rischio di incoerenze. Il Fiscal Agent risolve questo problema automatizzando le risposte di primo livello, mantenendo il tono di voce Fiscozen e delegando al Customer Success Consultant solo i casi complessi.

Obiettivi specifici

🎯
Risposte precise e affidabili

L'agente usa esclusivamente la knowledge base aziendale come fonte. Non inventa dati fiscali.

👤
Personalizzazione per cliente

Ogni risposta tiene conto del regime fiscale, del fatturato e del consulente assegnato al cliente.

💬
Tono di voce coerente

Il sistema prompt applica le linee guida Fiscozen a ogni risposta, senza deroghe.

🛒
Escalation intelligente

Quando la domanda è ambigua o rischiosa, l'agente rimanda al Customer Success Consultant assegnato.

Perimetro della demo

La demo opera su un campione di 4 clienti fittizi (Mario Rossi, Giulia Verdi, Luca Martini, Elena Riva) e due documenti fiscali rappresentativi. L'interfaccia è a riga di comando (CLI), con input via terminale o flag.

02 — Architettura

Scelte progettuali

Il sistema combina tre componenti distinti — recupero del contesto fiscale (RAG), lookup del profilo cliente, generazione del linguaggio — orchestrati in un singolo prompt strutturato. Ogni scelta è motivata da un requisito preciso.

Retrieval
RAG con LlamaIndex
Cosa fa

I documenti fiscali (.docx) vengono indicizzati in un VectorStoreIndex. Ad ogni domanda, il sistema recupera i 4 chunk più semanticamente rilevanti (512 token, overlap 64) e li inserisce nel prompt.

⚠ Perché

Il modello LLM non può memorizzare l'intero corpus fiscale nel contesto. Il RAG garantisce che la risposta sia basata su fonti verificabili, riducendo le allucinazioni.

Embedding
HuggingFace locale — paraphrase-multilingual-MiniLM-L12-v2
Cosa fa

Gli embedding vettoriali dei documenti e delle query vengono calcolati localmente, senza chiamate API esterne. Il modello scelto è ottimizzato per 50+ lingue, incluso l'italiano.

⚠ Perché

Azzera i costi di embedding (nessuna quota OpenAI consumata per il RAG). Il modello multilingue gestisce correttamente termini fiscali italiani senza fine-tuning.

Generazione
OpenAI GPT — temperatura 0.2
Cosa fa

Il modello GPT riceve un prompt strutturato (system + user) e genera la risposta finale in italiano. La temperatura è impostata a 0.2 per massimizzare la coerenza delle risposte.

⚠ Perché

Una temperatura bassa riduce la variabilità e le risposte creative non pertinenti, che in ambito fiscale possono essere fuorvianti. La qualità del linguaggio di GPT supera i modelli open-source per l'italiano.

Prompt design
Separazione system prompt / user prompt
Cosa fa

Il system prompt contiene il tono di voce (fisso, caricato da file) e le regole operative. Il user prompt è costruito dinamicamente con: domanda, dati del cliente, contesto fiscale dal RAG.

⚠ Perché

Separare le istruzioni permanenti dai dati dinamici rende il tono di voce inviolabile e semplifica l'aggiornamento indipendente di ognuno dei tre blocchi senza toccare il codice.

Dati cliente
Excel + Pandas — lookup per nome e cognome
Cosa fa

I dati del cliente (regime, cassa, consulente, fatturato, data apertura P.IVA) sono letti da un file .xlsx via Pandas. Il DataFrame viene caricato in memoria una sola volta e riusato per ogni query.

⚠ Perché

Excel è già il formato nativo usato dai team operativi Fiscozen. Eliminare un layer di database riduce la complessità infrastrutturale nella fase demo, mantenendo un'interfaccia familiare per il team.

Escalation
Escalation al consulente — regola nel system prompt
Cosa fa

Il system prompt istruisce il modello a rimandare al Customer Success Consultant assegnato (letto dai dati del cliente) quando la domanda è complessa, ambigua o a rischio per il cliente.

⚠ Perché

Gestire l'escalation via prompt — anziché con logica applicativa — permette di affinare la soglia di delegazione modificando solo testo, senza deploy di codice. Il nome del consulente è sempre personalizzato.

03 — Integrazioni

Componenti e dipendenze

Componente Libreria / Servizio Tipo Ruolo nel sistema
LLM — Generazione openai >= 1.0 API esterna Genera la risposta finale in italiano. Riceve il prompt strutturato e restituisce il testo per il cliente.
RAG — Orchestrazione llama-index-core >= 0.10 Locale Gestisce indicizzazione vettoriale e retrieval. Costruisce il VectorStoreIndex dai documenti e risponde alle query con i chunk più rilevanti.
Embedding — Vettorializzazione llama-index-embeddings-huggingface
sentence-transformers		 Locale Converte testo in vettori numerici. Modello: paraphrase-multilingual-MiniLM-L12-v2. Gira in locale, senza chiamate API.
Lettura documenti llama-index-readers-file
docx2txt, python-docx		 File locale Legge e analizza i file .docx della knowledge base fiscale. Converte il contenuto in nodi testuali per l'indicizzazione.
Dati cliente pandas >= 2.0
openpyxl >= 3.1		 File locale Legge customer_data.xlsx. Esegue il lookup per nome e cognome. Formatta il profilo cliente da inserire nel prompt.
Configurazione ambiente python-dotenv >= 1.0 Config Carica OPENAI_API_KEY dal file .env locale. Mantiene le credenziali fuori dal codice sorgente.

512 token con overlap di 64 token

Lingua
