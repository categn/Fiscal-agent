01 — Obiettivo

Overview

Fiscal Agent è un assistente conversazionale AI che risponde in tempo reale alle domande fiscali dei clienti Fiscozen, personalizzando ogni risposta con i dati specifici del cliente e il contenuto della knowledge base aziendale.

I consulenti e i clienti Fiscozen si trovano spesso a porre domande ricorrenti su regime forfettario, contributi previdenziali, fatturazione e scadenze. Rispondere manualmente a ogni richiesta richiede tempo e comporta il rischio di incoerenze. Il Fiscal Agent risolve questo problema automatizzando le risposte di primo livello, mantenendo il tono di voce Fiscozen e delegando al Customer Success Consultant solo i casi complessi.

Obiettivi specifici

🎯
Risposte precise e affidabili

L'agente usa esclusivamente la knowledge base aziendale come fonte. Non inventa dati fiscali.

👤
Personalizzazione per cliente

Ogni risposta tiene conto del regime fiscale, del fatturato e del consulente assegnato al cliente.

💬
Tono di voce coerente

Il sistema prompt applica le linee guida Fiscozen a ogni risposta, senza deroghe.

🛒
Escalation intelligente

Quando la domanda è ambigua o rischiosa, l'agente rimanda al Customer Success Consultant assegnato.

Perimetro della demo

La demo opera su un campione di 4 clienti fittizi (Mario Rossi, Giulia Verdi, Luca Martini, Elena Riva) e due documenti fiscali rappresentativi. L'interfaccia è a riga di comando (CLI), con input via terminale o flag.

02 — Architettura

Scelte progettuali

Il sistema combina quattro componenti distinti — recupero del contesto fiscale (RAG), ricerca web su fiscozen.it, lookup del profilo cliente, generazione del linguaggio — orchestrati in un flusso sequenziale. Ogni scelta è motivata da un requisito preciso.

Retrieval
RAG con LlamaIndex
Cosa fa

I documenti fiscali (.docx) vengono indicizzati in un VectorStoreIndex. L'indice è persistito su disco (storage/): viene costruito solo al primo avvio e ricaricato nei successivi. Ad ogni domanda, il retriever recupera i 4 chunk più semanticamente rilevanti (512 token, overlap 64) e li passa come testo al prompt — senza alcuna chiamata LLM interna da parte di LlamaIndex.

⚠ Perché

Il modello LLM non può memorizzare l'intero corpus fiscale nel contesto. Il RAG garantisce che la risposta sia basata su fonti verificabili, riducendo le allucinazioni.

Embedding
HuggingFace locale — BAAI/bge-m3
Cosa fa

Gli embedding vettoriali dei documenti e delle query vengono calcolati localmente, senza chiamate API esterne. Il modello scelto è ottimizzato per 100+ lingue, incluso l'italiano, con qualità di retrieval superiore ai modelli multilingue standard.

⚠ Perché

Azzera i costi di embedding (nessuna quota OpenAI consumata per il RAG). Il modello multilingue gestisce correttamente termini fiscali italiani senza fine-tuning.

Generazione
OpenAI GPT — temperatura 0.4
Cosa fa

Il modello GPT riceve un prompt strutturato (system + user) e genera la risposta finale in italiano. La temperatura è impostata a 0.4 per bilanciare coerenza e naturalezza del tono di voce.

⚠ Perché

Una temperatura nel range 0.3–0.5 è ideale per un assistente: abbastanza stabile da non inventare dati fiscali, abbastanza fluida da risultare naturale nel tono Fiscozen.

Web search
Google Custom Search — fallback su fiscozen.it
Cosa fa

Se il RAG non trova chunk rilevanti (score < soglia), il sistema estrae le parole chiave fiscali dalla domanda tramite LLM e le usa per cercare su fiscozen.it via Google Custom Search API. I top-5 snippet vengono aggiunti al contesto.

⚠ Perché

Estendere il contesto al sito pubblico Fiscozen copre guide, servizi e aggiornamenti non presenti nei documenti locali — senza fonti esterne. Le keyword sostituiscono la domanda completa per non trasmettere dati personali a Google.

Prompt design
Prompt caricati da file — configs/prompts/
Cosa fa

Il system prompt e il prompt di estrazione keyword sono caricati da file in configs/prompts/. Il user prompt è costruito dinamicamente con: domanda, dati del cliente, contesto (RAG o web).

⚠ Perché

Separare i prompt dal codice permette di modificare tono, regole operative e logica di escalation senza deploy. Ogni file è indipendente e versionabile.

Dati cliente
Excel + Pandas — lookup per nome e cognome
Cosa fa

I dati del cliente (regime, cassa, consulente, fatturato, data apertura P.IVA) sono letti da un file .xlsx via Pandas. Il DataFrame viene caricato in memoria una sola volta e riusato per ogni query.

⚠ Perché

Excel è già il formato nativo usato dai team operativi Fiscozen. Eliminare un layer di database riduce la complessità infrastrutturale nella fase demo, mantenendo un'interfaccia familiare per il team.

Escalation
Escalation — solo nel codice
Cosa fa

Se né il RAG né la web search trovano contesto, generate_answer() restituisce direttamente un messaggio di escalation con il nome del consulente assegnato al cliente — senza chiamare l'LLM. Il system prompt non gestisce più questo caso: contiene solo istruzioni per non inventare dati quando il contesto è insufficiente.

⚠ Perché

Accentrare l'escalation nel codice è deterministico e non costa chiamate LLM. Evita la duplicazione logica tra codice e prompt che rendeva il comportamento ambiguo.

Osservabilità
Logging strutturato — stdlib logging
Cosa fa

Ogni passo del flusso emette un log su console con timestamp e livello. I livelli usati: INFO per i passi principali (fonte scelta, escalation, caricamento indice), DEBUG per i dettagli tecnici (user prompt completo, chunk score, keyword estratte), WARNING per configurazione mancante, ERROR per errori di rete nella web search. Il logger è configurato in main.py e propagato a utils.py tramite getLogger(__name__).

⚠ Perché

Permette allo sviluppatore di vedere esattamente come viene costruito lo user prompt e quale fonte viene usata per ogni risposta, senza modificare il codice. In produzione è sufficiente alzare il livello a INFO per ridurre il rumore.

03 — Integrazioni

Componenti e dipendenze

Componente Libreria / Servizio Tipo Ruolo nel sistema
LLM — Generazione openai >= 1.0 API esterna Genera la risposta finale in italiano. Riceve il prompt strutturato e restituisce il testo per il cliente.
RAG — Orchestrazione llama-index-core >= 0.10 Locale Gestisce indicizzazione vettoriale e retrieval puro. Costruisce il VectorStoreIndex dai documenti e recupera i chunk più rilevanti senza sintetizzare con un LLM interno.
Embedding — Vettorializzazione llama-index-embeddings-huggingface
sentence-transformers		 Locale Converte testo in vettori numerici. Modello: BAAI/bge-m3. Gira in locale, senza chiamate API. Ottimizzato per retrieval multilingue (100+ lingue, italiano incluso).
Lettura documenti llama-index-readers-file
docx2txt		 File locale Legge e analizza i file .docx della knowledge base fiscale. Converte il contenuto in nodi testuali per l'indicizzazione.
Dati cliente pandas >= 2.0
openpyxl >= 3.1		 File locale Legge customer_data.xlsx. Esegue il lookup per nome e cognome. Formatta il profilo cliente da inserire nel prompt.
Web search requests >= 2.31
Google Custom Search API		 API esterna Fallback se il RAG non trova contesto rilevante. Cerca su fiscozen.it usando keyword estratte dalla domanda. 100 chiamate/giorno gratuite.
Configurazione ambiente python-dotenv >= 1.0 Config Carica le variabili d'ambiente dal file .env locale (chiavi API, modello, temperatura, soglia RAG). Mantiene le credenziali fuori dal codice sorgente.
Logging logging (stdlib) Locale Log strutturati su console con timestamp. DEBUG: user prompt completo, chunk score, keyword estratte. INFO: fonte usata, escalation, caricamento indice. WARNING/ERROR: credenziali mancanti, errori di rete.
